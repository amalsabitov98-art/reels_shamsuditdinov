# Аудит и границы версии 1.1

Дата: 2026-09-07. Это не заявление о готовности полного AI-конвейера.

## Варианты

| Путь | Что даёт | Ограничение |
| --- | --- | --- |
| Браузер Flow | Использует текущий вход и доступ пользователя | Кнопки меняются; режим «Агент» не проверен |
| Официальный Gemini video API | Документированные запросы и идентификаторы результатов | Отдельный платный доступ; не подключён без выбора пользователя |
| Flow вручную + локальная сборка | Генеративный монтаж сохраняется, импорт/экспорт не зависят от UI Flow | Нужно проверить и скачать результат каждой части |
| Обычный локальный монтаж | Нет внешней генерации | Не равно генеративному монтажу; не подменяет исходную задачу |

Официальные источники для API: https://ai.google.dev/gemini-api/docs/video
и https://ai.google.dev/gemini-api/docs/pricing . Подписка Flow не трактуется
как разрешение автоматически оплачивать API. Ключей и платных вызовов не добавлено.

## Доказанные дефекты

- `image/*` считался подходящим для MP4 — исправлен разбор accept.
- HTTP 2xx (в том числе начало resumable upload) не доказывает готовность ассета.
  Теперь требуется готовая строка с именем; неподтверждение — остановка.
- Подстрока, число плиток и текст поиска не доказывают загрузку нужной части.
  Строки обработки больше не считаются готовыми.
- Выбор первой вкладки мог переключать проекты. Нужен один проект; очередь
  передаёт выбранный URL дочерним шагам, без молчаливого переподключения.
- Отсутствие Ingredients больше не позволяет отправку в неизвестный режим.
- Таймаут и ошибка останавливают очередь; следующие части не отправляются.
- Автоскачивание результатов по времени/порядку из `run-flow` убрано.
  Старые standalone-скрипты скачивания/сборки оставлены для совместимости,
  но новый маршрут студии их не использует и не объявляет безопасными.
- Helper блокирует параллельные операции. Импорты имеют уникальные имена,
  SHA-256 и привязку к части. Экспорт проверяет комплект до начала работы.
- Старый финал не перезаписывается при ошибке кодирования; при успехе есть копия.
- Windows installer проверяет коды выхода, а не печатает успех после ошибки pip/npm.

## Проверки и границы

`npm test`: тесты типов загрузки, имён/обработки ассетов, выбора проекта,
длительности/звука и smoke-проверки. Реальный офлайн-тест FFmpeg создаёт
красную и синюю части со звуком, собирает 1080×1920, проверяет порядок по пикселям,
длительность и сохранность финала при неполном/повреждённом комплекте.

HTTP-тест выделен отдельно: `REELS_TEST_HTTP=1 npm test`
(PowerShell: `$env:REELS_TEST_HTTP='1'; npm test`). Он импортирует файлы через API,
проверяет блокировку задач, сборку и скачивание. В среде разработки его запуск
остановлен ограничением доступа; здесь он НЕ считается пройденным.

Windows installer, браузер пользователя, текущий интерфейс Flow,
визуальный результат генерации и точность речи полного ролика здесь НЕ проверены.
Диагностика только снимает структуру видимых элементов; это не live E2E-тест.
Распознавание ассетов по DOM остаётся эвристикой и не идентифицирует содержимое:
одинаковые имена файлов в проекте могут быть неоднозначны. При сомнении используйте
ручной импорт и предпросмотр. Во время аудита генерация в аккаунте пользователя
не запускалась.
